(อ่านหัวข้อ 3 ให้จบก่อนสรุปตัวเลขใด ๆ)

## 1. ได้อะไร

| ชิ้น | อะไร | เข้าถึงยังไง |
|---|---|---|
| **แท็บ `บันทึกโค้ช`** | บทสนทนาห้องโค้ช 1,695 แถว (1 เม.ย. – 28 ก.ย. 2569) | Google Sheets — เปิดอ่านได้ ไม่ต้องติดตั้งอะไร |
| **`/api/v1/employees`** | รายชื่อพนักงาน (ชื่อเล่น · ตำแหน่ง · LINE userId) | HTTP + คีย์ |
| **`/api/v1/groups`** | รายการกลุ่ม LINE (group id + ชื่อกลุ่ม) | HTTP + คีย์ |

**ไม่มีสิทธิ์เข้าฐานข้อมูลโดยตรง** และไม่จำเป็น — ข้อมูลห้องโค้ชฉบับสมบูรณ์อยู่ในชีต
ส่วนในฐานข้อมูลมีแค่ 19 ข้อความ (เก็บเฉพาะ 90 วันล่าสุด แล้วลบทิ้ง) ชีตคือตัวถาวร

### เรียก API

```bash
curl -H "X-API-Key: <คีย์ที่ได้รับ>" https://srv1793506.hstgr.cloud/api/v1/employees
```

## 2. โครงตาราง `บันทึกโค้ช` — 1 แถว = 1 ข้อความ

| คอลัมน์ | ความหมาย |
|---|---|
| `วันที่` | `YYYY-MM-DD` (เขตเวลาไทย) |
| `เวลา` | `HH:MM` |
| `รหัสเคส` | เลข 4–5 หลักที่ทีมใช้อ้างถึงลูกค้าราย 1 คน — **ดูข้อ 3.1** |
| `ผู้พูด` | ชื่อเล่นพนักงาน (ไม่มี LINE userId ในชีตนี้เลย) |

| `ทีม` | ทีมขายของผู้พูด — **ว่าง 70% ดูข้อ 3.4** |
| `ข้อความ` | เนื้อข้อความตามที่พิมพ์จริง |
| `สถานะเคส` | สถานะของเคสตอนนั้น (ถ้ามีการกรอก) |
| `ชนิด` | ประเภทเหตุการณ์ — **ดูข้อ 3.3** |

| `หมายเหตุ` | ของแถมจากระบบเก่า (ระดับ A/B/C, จำนวนครั้งที่อัปเดต) |

**บริบท**: จูเนียร์รายงานเคสที่ทำอยู่เข้าห้องนี้ ซีเนียร์อ่านแล้วให้คำแนะนำกลับ
เคยมี chatbot ช่วยตอบอยู่ช่วงหนึ่ง (ปิดไปแล้ว)

## 3. อ่านให้ถูก — 7 กับดักที่เจอมาแล้วจริง

### 3.1 `รหัสเคส` มีได้หลายรหัสในช่องเดียว
จูเนียร์รายงานวันละ 1 ข้อความคร่อมหลายเคส → ช่องนี้เก็บเป็น `8029 8074 8059` คั่นช่องว่าง
(5 แถว) → **Pivot ตรง ๆ ไม่ได้ ต้องแยกช่องว่างก่อน** ถ้าจะนับต่อเคส

### 3.2 ★ `บอท AI (ระบบเดิม)` 39 แถว — ห้ามเอาไปสอนโมเดล
เป็นคำตอบของ chatbot ตัวเก่า ไม่ใช่คำแนะนำของคน
เอาไปเป็นข้อมูลฝึกเท่ากับให้โมเดลเรียนจากเอาต์พุตตัวเอง → กรอง `บทบาท != 'บอท AI (ระบบเดิม)'` ทุกครั้ง

### 3.3 ★★ ข้อมูลไม่ได้กระจายทั้งปี — กระจุกที่ เม.ย.–พ.ค.

| เดือน (2569) | แถว |
|---|---|
| เม.ย. | **943** |
| พ.ค. | **606** |
| มิ.ย. | 32 |
| ก.ค. | 107 |
| **ส.ค.** | **0 — ไม่มีเลย** |
| ก.ย. | 7 |

เม.ย.+พ.ค. = **91% ของทั้งหมด** · ส.ค. หายทั้งเดือน เพราะ chatbot ถูกปิดแล้วห้องเงียบลง
ระบบเก็บอัตโนมัติเพิ่งเริ่มทำงาน 28 ก.ย.

→ **เปรียบเทียบข้ามเดือนหรือดูเทรนด์รายเดือนทำไม่ได้** · วิเคราะห์ได้จริงคือ เม.ย.–พ.ค.

### 3.4 `ทีม` ว่าง 1,183 แถว (70%)
ชื่อ LINE ของผู้พูด 7 คนยังจับคู่กับทะเบียนพนักงานไม่ได้ (ตั้งชื่อแฟนซี/มีอิโมจิ)
→ **แบ่งผลตามทีมไม่ได้** · ใช้ `ผู้พูด` เป็นหน่วยวิเคราะห์แทน

### 3.5 ★ "ซีเนียร์" เกือบทั้งหมดคือคนเดียว

| ซีเนียร์ | ความเห็น |
|---|---|
| เฟิร์ส | **154 (78%)** |
| อุ้ม | 23 |
| โอ๊ต | 13 |
| นวล | 7 |

"วัดคุณภาพการตอบของซีเนียร์" จึงเป็นการวัดเฟิร์สเป็นหลัก
อีก 3 คนจำนวนน้อยเกินกว่าจะสรุปอะไรได้

### 3.6 จูเนียร์ 1,422 : ซีเนียร์ 197 — ไม่สมดุลตามธรรมชาติ
จูเนียร์รายงานทุกวันทุกเคส ซีเนียร์คอมเมนต์เฉพาะเคสที่ต้องแนะ
**ไม่ใช่สัญญาณว่าซีเนียร์ไม่ตอบ** · อัตราตอบกลับต้องคิดต่อเคส ไม่ใช่ต่อข้อความ

### 3.7 ไม่ใช่คู่ถาม–ตอบที่จับคู่ไว้แล้ว
แถวเรียงตามเวลา ไม่ได้ผูกว่าความเห็นไหนตอบรายงานไหน
→ ต้องจับคู่เองด้วย `รหัสเคส` + ความใกล้กันของเวลา
ข้อความบางส่วนในช่วง `ชีตเดิม-ช่องผิด` (37 แถว) ถูกกรอกผิดช่องมาแต่เดิม
ระบบจึงลงบทบาทเป็น `(ไม่ทราบ)` ไว้ **ไม่ได้เดาให้** — ถ้าจะใช้ต้องอ่านเองว่าใครพูด

## 4. สิ่งที่ไม่มีในชุดนี้

- **รูป/ไฟล์ในห้อง** — LINE ส่งมาแค่ตัวชี้ ตัวไฟล์ไม่ได้ถูกเก็บ
- **LINE userId ของคนในชีต** — ตัดออกตั้งใจ (`ผู้พูด` เป็นชื่อเล่น)
- **ห้องอื่น** — ให้เฉพาะห้อง Sale Coaching · ห้องลีด/จัดซื้อ/เทิร์นรถ/แชทลูกค้า ไม่รวมอยู่ในชุดนี้
- **ผลลัพธ์ปลายทางของเคส** — ชีตนี้ไม่บอกว่าเคสที่ซีเนียร์แนะแล้วปิดการขายได้จริงไหม
  (ข้อมูลนั้นอยู่คนละไฟล์ ยังไม่ได้เชื่อมกัน) → **วัด "คำแนะนำนี้ทำให้ขายได้" จากชุดนี้ไม่ได้**

## 5. ข้อตกลงการใช้

- อ่านอย่างเดียว · ห้ามทำสำเนาส่งต่อบุคคลที่สาม
- ในข้อความมีชื่อลูกค้า เบอร์โทร รายละเอียดการเงินที่พนักงานพิมพ์กันเอง
  ถือเป็นข้อมูลส่วนบุคคลตาม PDPA — ใช้เพื่อวัตถุประสงค์ที่ตกลงไว้เท่านั้น
- ถ้าเอาไปฝึกโมเดล ต้องไม่ส่งข้อมูลนี้ออกไปยังบริการภายนอกที่เก็บข้อมูลไว้ฝึกต่อ
  โดยไม่แจ้งเจ้าของข้อมูลก่อน
- คีย์ API เป็นของคุณคนเดียว ห้ามแชร์ — เพิกถอนได้ทันทีโดยไม่กระทบผู้อื่น
