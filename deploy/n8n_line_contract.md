# สัญญาเชื่อมต่อ n8n → Oxlet (LINE webhook)

เอกสารส่งมอบให้คนที่ตั้งค่า n8n · **ฝั่งรับ (Oxlet) เป็นคนกำหนดสัญญานี้** เพราะเป็นเจ้าของฐานข้อมูล
— ฝั่ง n8n ไม่ต้องออกแบบรูปแบบข้อมูลเอง

---

## กฎข้อเดียวที่ต้องจำ

> **ส่ง body ดิบที่ LINE ส่งมา ทั้งก้อน โดยไม่แปลงอะไรเลย**

ห้าม map field ใหม่ · ห้ามตัดอะไรออก · ห้ามสร้างรูปแบบของตัวเอง

**ทำไม** — LINE ส่งของครบอยู่แล้ว และมีฟิลด์ที่ระบบใช้จริงซึ่ง**มองไม่ออกว่าสำคัญ**:

| ฟิลด์ | ระบบเอาไปทำอะไร | ถ้าหาย |
|---|---|---|
| `destination` | บอกว่า **บัญชี LINE ตัวไหน**เป็นเจ้าของ event | แยกไม่ออกว่าใครคุยกับบอทตัวไหน · ดึงโปรไฟล์ด้วย token ผิดตัว (404) |
| `events[].source.userId` | ตัวตนของคน (ผูกกับโปรไฟล์ + ชื่อเล่นพนักงาน) | ไม่รู้ว่าใครพูด |
| `events[].source.groupId` | แยกคลังแชทรายกลุ่ม + จับคู่เคสเบิก-คืน | ข้อความลอย ไม่รู้มาจากกลุ่มไหน |
| `events[].message.id` | กันเก็บซ้ำ (LINE ยิง webhook ซ้ำได้) | ข้อความซ้ำในฐานข้อมูล |
| `events[].timestamp` | เวลาที่พูดจริง | เวลาเพี้ยนไปเป็นเวลาที่ n8n ส่ง |

**เคยพลาดมาแล้ว 2 รอบ** (ก.ย.69): รอบแรกส่งผลของโหนด "Get Group Summary" (`{groupId, groupName}`)
มาแทน body ดิบ → กลุ่มเข้าระบบแต่ข้อความไม่เข้าเลย · รอบสองส่ง `{}` ว่างเปล่าเพราะโหนดต่อผิดที่

---

## ตั้งค่า 2 จุด

### 1. LINE Developers Console (ทำทุก channel)

Messaging API → **Webhook URL** = URL ของ Webhook node ใน n8n (**Production URL** ไม่ใช่ `webhook-test`)
→ เปิด **Use webhook**

**2 channel ชี้มาที่ URL เดียวกันได้** — ฝั่ง Oxlet แยกเองจาก `destination`
(จะแยกเป็นคนละ node ก็ได้ ไม่ต่างกันสำหรับฝั่งรับ)

### 2. n8n

**Webhook node** — `Respond: Immediately` (ตอบ 200 ทันที)

> ⚠️ **ห้ามตั้งให้รอผลจาก HTTP node ก่อนตอบ** — LINE รอ response แป๊บเดียวแล้ว retry
> ถ้าไปรอฝั่งเรา จะได้ event ซ้ำรัวๆ (ฝั่งเรากันซ้ำด้วย `message.id` อยู่ แต่เปลืองเปล่าๆ)
> LINE ไม่ได้อ่าน body ที่ตอบกลับ ขอแค่ 200

**HTTP Request node** — ต่อจาก Webhook node

| ช่อง | ค่า |
|---|---|
| Method | `POST` |
| URL | `https://srv1793506.hstgr.cloud/api/line/group_ingest` |
| Header | `X-Cron-Secret: <CRON_SECRET>` |
| Body | JSON · `={{ JSON.stringify($('Webhook').first().json.body) }}` |
| On Error | `Continue` (ฝั่งเราล่มไม่ควรทำให้ workflow ตาย) |
| Timeout | 15000 |

**`$('Webhook')` ต้องตรงกับชื่อ node จริงบน canvas** — ใส่ผิด = expression พัง n8n จะไม่ยิงออกมาเลย
(อ้างชื่อ node ตรงๆ แบบนี้ทำให้วางโหนดไว้ตรงไหนในสายก็ทำงาน ไม่ต้องต่อจาก Webhook เท่านั้น)

ไฟล์สำเร็จรูปวางบน canvas ได้เลย: [n8n_send_chat_to_oxlet.json](n8n_send_chat_to_oxlet.json)

## ฝั่ง Oxlet ตอบอะไรกลับ (ไว้ดีบักใน n8n execution)

n8n **ไม่ต้องเอาไปทำอะไรต่อ** — มีไว้ให้เปิด execution แล้ววินิจฉัยได้ทันทีว่าข้อมูลเข้าครบไหม

```json
{
  "ok": true,
  "count": 0,            // กลุ่มที่เพิ่ง "รู้จักใหม่/อัปเดตชื่อ" รอบนี้
  "groups": [],
  "removed": 0,          // กลุ่มที่บอทถูกเตะออก
  "events": 1,           // ★ อ่าน event ได้กี่อัน — 0 = body ไม่ถูกส่งมา (ดูกฎข้อเดียวด้านบน)
  "textEvents": 1,       // ในนั้นเป็นข้อความตัวอักษรกี่อัน
  "forGroup": 0,         // ตรงกับ "กลุ่มที่ตั้งดักเก็บเคสเบิก-คืน" กี่อัน
  "listening": true,     // เปิดดักเก็บเคสอยู่ไหม
  "storeChat": true,     // เปิดเก็บแชทอยู่ไหม
  "chatTotal": 123,      // ⚠️ ยอด "ก่อน" รอบนี้ (งานเก็บทำใน background) → ยิงรอบ 2 ถึงเห็นขยับ
  "lastStore": {...}     // ผลการเก็บรอบก่อนหน้า {at, saved, skipped, events, error}
}
```

**อ่านผลอย่างไร**

| เห็นอะไร | แปลว่า |
|---|---|
| `events` ≥ 1 | ✅ body มาครบ |
| `events: 0` | ❌ body ไม่ใช่ของ LINE → ดู `line_ingest_last` ฝั่งเซิร์ฟเวอร์ว่าได้อะไรมา |
| HTTP 403 | `X-Cron-Secret` ไม่ตรง |
| `lastStore.error` มีค่า | เก็บลงฐานข้อมูลไม่ผ่าน (มักเพราะยังไม่ `migrate`) |

## ตรวจฝั่งเซิร์ฟเวอร์

```bash
cd /opt/oxlet && .venv/bin/python manage.py checkout_status --out /tmp/s.txt && cat /tmp/s.txt
```

- **ข้อ 2.5** โผล่ = อ่าน event ไม่ได้ · บอกด้วยว่า body ที่ได้มาหน้าตายังไง
- **ข้อ 5.5** = คลังแชท **แยกตามบัญชี** → เห็นว่าบัญชีใหม่เริ่มส่งข้อมูลเข้ามาหรือยัง
  (ขึ้น `(ไม่ทราบ)` = `destination` หายระหว่างทาง)
