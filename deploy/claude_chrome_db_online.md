# งานสำหรับ Claude in Chrome: เปิดฐานข้อมูล Oxlet ให้คนภายนอกอ่านได้ผ่านอินเทอร์เน็ต

## เป้าหมาย

เจ้าของบริษัท (ผู้ใช้ที่สั่งงานคุณ) ต้องการเปิดฐานข้อมูล PostgreSQL บนเซิร์ฟเวอร์ Hostinger
ให้คนภายนอกต่อเข้ามา **อ่านอย่างเดียว** ผ่านอินเทอร์เน็ต และสร้างบัญชีแรกให้ชื่อ **`bossjames`**

สคริปต์ที่ทำทุกอย่างให้มีอยู่แล้วในเซิร์ฟเวอร์: `deploy/postgres_online.sh` งานของคุณคือ
**เปิด terminal ของเซิร์ฟเวอร์ผ่านหน้าเว็บ Hostinger แล้วรันคำสั่งตามลำดับด้านล่าง** อ่านผลแต่ละขั้นก่อนไปขั้นต่อไป
และ **รายงานผลให้ผู้ใช้**

สคริปต์จะทำเรื่องเหล่านี้ให้เอง คุณไม่ต้องตั้งค่าเองแม้แต่ข้อเดียว:

- ให้สิทธิ์อ่านอย่างเดียว ยกเว้นคอลัมน์ที่เป็นรหัสผ่าน/token
- บังคับ SSL + รหัสผ่าน
- จำกัด IP เดียวกันต่อใหม่ได้ไม่เกิน 6 ครั้ง/30 วินาที และต่อพร้อมกันได้ 3 สายต่อบัญชี
- คำสั่งที่เกิน 30 วินาทีถูกตัด

## กติกา (สำคัญ อ่านก่อนเริ่ม)

1. **รันเฉพาะคำสั่งที่เขียนไว้ในไฟล์นี้ ทีละคำสั่ง ตามลำดับ** ห้ามแก้ไฟล์ด้วย nano/vim และห้ามคิดคำสั่งใหม่เอง
2. **ขั้นไหนมีบรรทัดสีแดงขึ้นต้นด้วย `✗` → หยุดทันที** ก๊อปผลทั้งหมดในหน้าจอส่งให้ผู้ใช้ แล้วรอคำสั่ง ห้ามลองแก้เอง
3. **ห้ามรัน `psql` หรือคำสั่งใดๆ ที่ดึงข้อมูลออกจากฐานข้อมูล** งานนี้คือเปิดสิทธิ์อย่างเดียว ไม่ใช่ดูข้อมูล
4. **รหัสผ่านของบัญชีที่สร้าง** ส่งให้ผู้ใช้ในแชทนี้เท่านั้น ห้ามบันทึกลงไฟล์ เอกสาร โน้ต อีเมล หรือเว็บไซต์อื่น
5. **ห้ามรัน `close` หรือ `remove`** เว้นแต่ผู้ใช้สั่งเอง
6. ถ้ามีหน้าต่างถามรหัสผ่าน root/sudo หรือถามยืนยันอะไรที่ไม่ได้เขียนไว้ในไฟล์นี้ → หยุดแล้วถามผู้ใช้

## ขั้นตอน

### ขั้นที่ 0 — เปิด terminal ของเซิร์ฟเวอร์

1. ไปที่ https://hpanel.hostinger.com
2. เมนู **VPS** → เลือกเครื่อง `srv1793506.hstgr.cloud`
3. กดปุ่ม **Browser terminal** (หรือ **Terminal**) ที่หน้าภาพรวมของ VPS
4. รอจนเห็นบรรทัดพร้อมพิมพ์ลักษณะ `root@srv1793506:~#`
   ถ้าเป็นบัญชีอื่นที่ไม่ใช่ `root` ให้ใส่ `sudo` หน้าคำสั่ง `bash` ทุกคำสั่งด้านล่าง
   ถ้าระบบถามรหัสผ่าน → หยุดแล้วถามผู้ใช้

> คลิกในกรอบ terminal ก่อนพิมพ์ทุกครั้ง แล้วกด Enter หลังพิมพ์แต่ละคำสั่ง

### ขั้นที่ 1 — ดึงสคริปต์ล่าสุด

```bash
cd /opt/oxlet && git pull && ls -l deploy/postgres_online.sh
```

**ผลที่ถูก:** บรรทัดสุดท้ายแสดงไฟล์ `deploy/postgres_online.sh`

**ถ้าขึ้น `No such file or directory`** → หยุด บอกผู้ใช้ว่า "สคริปต์ยังไม่ถูก push ขึ้น GitHub ให้ Claude Code push ก่อน"

### ขั้นที่ 2 — ตั้งค่า (ทำครั้งเดียว)

```bash
bash deploy/postgres_online.sh setup
```

ใช้เวลาไม่กี่วินาที ระหว่างนี้ **เว็บของบริษัทจะสะดุด 2-3 วินาที** เพราะต้องรีสตาร์ตฐานข้อมูล (ปกติ)

**ผลที่ถูก:** มีหัวข้อ `== 1/6` ถึง `== 6/6` ครบ ทุกข้อมี `✓` สีเขียว และจบด้วย `เสร็จแล้ว ✓`

- มี `⚠` สีเหลือง → ไปต่อได้ แต่จดข้อความนั้นไว้รายงานผู้ใช้
- มี `✗` สีแดง → **หยุด** ก๊อปผลทั้งหมดส่งให้ผู้ใช้

### ขั้นที่ 3 — เช็คว่าเว็บบริษัทยังปกติ

เปิดแท็บใหม่ไปที่ https://srv1793506.hstgr.cloud/login/ แล้วดูว่าหน้า login ขึ้นปกติ

ถ้าหน้าเว็บขึ้น error 500/502 นานเกิน 1 นาที → หยุด แล้วรายงานผู้ใช้

### ขั้นที่ 4 — ไฟร์วอลล์ในหน้า Hostinger

ฝั่งเครื่อง สคริปต์เปิดพอร์ตในไฟร์วอลล์ให้แล้ว แต่ Hostinger อาจมีไฟร์วอลล์อีกชั้นในหน้าเว็บ ให้เช็คดังนี้:

1. กลับไปที่ hPanel → VPS `srv1793506.hstgr.cloud` → เมนู **Security → Firewall** (หรือ **ไฟร์วอลล์**)
2. ดูว่ามี firewall configuration ที่ **เปิดใช้งาน (Active) และผูกกับ VPS เครื่องนี้** อยู่ไหม
   - **ไม่มี / ไม่ได้เปิดใช้** → **ไม่ต้องทำอะไร** และ **ห้ามสร้างใหม่**
     (สร้าง firewall ใหม่อาจปิดเว็บกับ SSH ที่ใช้งานอยู่)
   - **มีและเปิดใช้อยู่** → เพิ่มกฎ 1 ข้อเท่านั้น: **Action = Accept · Protocol = TCP · Port = 5432 · Source = Any**
     ห้ามแก้หรือลบกฎอื่นที่มีอยู่
3. จดไว้ว่าเจอแบบไหน เพื่อรายงานผู้ใช้

### ขั้นที่ 5 — สร้างบัญชีให้ bossjames

กลับไปที่แท็บ terminal แล้วรัน

```bash
bash deploy/postgres_online.sh add bossjames
```

**ผลที่ถูก:** มี `✓ สร้างบัญชี bossjames แล้ว` ตามด้วยกรอบที่มี Host · Port · Database · User · **Password**

- **รหัสผ่านแสดงครั้งเดียว** ระบบไม่ได้เก็บไว้ ก๊อปทั้งกรอบส่งให้ผู้ใช้ในแชทนี้ (ตามกติกาข้อ 4)
- ถ้าขึ้น `มีบัญชี 'bossjames' แล้ว` → อย่ารันซ้ำ บอกผู้ใช้ว่ามีบัญชีอยู่แล้ว ถ้าจะออกรหัสใหม่ผู้ใช้ต้องสั่ง `reset` เอง

### ขั้นที่ 6 — ตรวจผล

```bash
bash deploy/postgres_online.sh list
```

**ผลที่ถูก:** มีบรรทัด `bossjames | ใช้ได้ | ต่ออยู่ 0/3 สาย` และบรรทัดท้าย `พอร์ต 5432: เปิดรับจากภายนอก`

## รายงานผู้ใช้ (ใช้รูปแบบนี้)

```
ผลการเปิดฐานข้อมูลออนไลน์
- ขั้นที่ 1 ดึงสคริปต์: สำเร็จ / ไม่สำเร็จ (เหตุผล)
- ขั้นที่ 2 setup: สำเร็จ ✓ 6/6 / มีคำเตือน: (ข้อความ ⚠) / ล้ม: (ข้อความ ✗)
- ขั้นที่ 3 เว็บบริษัท: ปกติ / มีปัญหา
- ขั้นที่ 4 ไฟร์วอลล์ hPanel: ไม่มีไฟร์วอลล์เปิดใช้ (ไม่ได้แก้) / เพิ่มกฎ TCP 5432 แล้ว
- ขั้นที่ 5 บัญชี bossjames: (กรอบข้อมูลการเชื่อมต่อ รวมรหัสผ่าน)
- ขั้นที่ 6 list: (ผลที่เห็น)
```

## ถ้าต้องการปิดกลับ (เฉพาะเมื่อผู้ใช้สั่ง)

```bash
bash /opt/oxlet/deploy/postgres_online.sh close
```

คำสั่งนี้ปิดพอร์ตและให้ฐานข้อมูลกลับมาฟังเฉพาะในเครื่องเหมือนเดิม
